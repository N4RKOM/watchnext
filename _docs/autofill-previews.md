## Interaction

- Entry methods offer Manual, YouTube (explicit Title search or Video link/ID), and Kinopoisk Unofficial title search. Explicit submit only; no background/keystroke fetch. Use existing pageCandidatesAction opaque handles for real next/previous/limit feedback, including empty filtered pages with real navigation. Candidate cards show actual image, title and year/type for films, channel/full duration for videos; unknown values are labeled, never guessed.
- Selecting a candidate retrieves its current server detail and automatically fills supported editable title/type/runtime/genres/source/watch/cover fields. Supported direct YouTube link success does the same. Clean flow has **no Apply proposal button** and no second approval; explicit Save is still required. Year/channel remain displayed review context, not invented persistent editable title fields. Absent optional fields remain blank; moods are never supplied by provider.
- Moods are selected manually and preserved across candidate replacement; untouched default movie type alone does not count as a dirty manual edit. Provider-supported runtime maps to exact minutes/seconds, while missing runtime/unknown type requires manual completion. Episodic imports also require manual numbering and explicit typical-episode-duration confirmation. Kinopoisk's FILM minutes mapping is shown as a concise editable runtime interpretation, not verified units/live access.
- Dirty means user metadata differs from initial/last accepted suggestion baseline, excluding mood choices. If a deliberate new selection/link would replace dirty metadata, show a clear Replace details / Keep my details confirmation that names replacement scope before applying. Declining changes no metadata or trusted review handle. Accepting binds the replacement to the current form revision; edits during awaiting/detail fetch invalidate earlier replacement consent. Such a late result cannot silently overwrite, attach a mismatched identity or erase the user's edits; offer deliberate reselection/updated confirmation. Clean selection remains automatic.
- Query/source change, cancellation, paging/new selection and group/member/context change invalidate late UI replies and old actionable candidate state. Field edit revision is checked independently from lookup generation. Failure, empty results or manual fallback preserves typed fields/moods/current valid review ownership. Switching the lookup selector does not relabel previously imported fields as manual. Explicit Start fresh manual entry clears imported fields/review and explains loss; genuinely dirty data needs clear confirmation. Input errors/duplicate/restore outcomes retain safe data and visible retry; pending save prevents conflicting replacement/reset.

## Identity, ownership and images

All source identities/retrieval/provenance/page tokens come from current server-owned reviews; client namespaces/IDs never grant save authority. Unchanged auto-populated values keep provider origin/deadline; actual corrections become user-origin by existing comparison. Missing required fields/mood/runtime block server save. Contribution-aware one-entry merge/confirmation and archived restoration preserve every contributor/history record. Contributor-only shared editing and live auth/group/context epoch, removal/rejoin/logout/recovery checks remain intact.

Reuse one safe preview component for candidate, selected review, watchlist, archive and detail. Validate provider URLs with existing youtubeThumbnail/kinopoiskPoster helpers, using actual returned/stored URLs only; no arbitrary server proxy/optimizer, URL fetch, image download/cache or synthesized art. Direct browser images use HTTPS allowlisted hosts and no-referrer, with useful alt/fallback and fixed 16:9 video / 2:3 poster layout. Missing, unsafe, expired or broken/cached-failed images use stable text fallback without blocking selection/save. The component must reset failure state when URL changes. Keyboard focus/announcements and narrow layout must stay stable.

Legacy/user-authored cover values remain stored with their existing ownership; this task does not erase them or change provenance just for display. Values outside the safe preview allowlist render honest fallback rather than arbitrary remote requests. Actual user correction to an allowed URL survives imported-field expiry; provider-owned expired cover clears normally. No new image rights gate or verified-license claim; no user-facing implementation/policy essay.

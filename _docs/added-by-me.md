## Delegated defaults

- Only the active account-group /watchlist offers All titles and Added by me. Default /watchlist is All; /watchlist?filter=mine is Mine, and filter=all is equivalent to All. Use real accessible navigation links with current selection and ordinary back/reload behavior. No account/member/group ID is placed in filter URLs. Invalid, duplicate or array-valued filter values safely show All with an honest unsupported-filter message; unrelated URL claims are never identity authority.
- Server reads always derive current mode/account/group/owned member from live guarded context, then Mine means an EXISTS contribution for that exact member on an active title in that group. Group ownership, personal progress/rating/note, another selected viewer or submitted ID does not imply contribution. One title appears once. Secondary metadata/contributor projections must match the visible title set without dropping any joint contributor.
- All contributors' names/colors/inactive status remain visible on Mine/All/detail. Mine changes only title inclusion, never attribution, histories, ordering, content metadata, ranking or picker scope. Provider/manual entries use the same contribution predicate. Existing safe previews/fallbacks remain.
- Removing one's own contribution drops the title from one's Mine while another adder retains it in Mine/All. Final removal archives it and excludes both active views; restoring with one's contribution returns the same ID/history to Mine. Creator removal does not delete prior contributions: current members still see inactive attribution/sole-added titles in All; removed account cannot access either filter.
- Legacy groups keep their existing shared All view/profile behavior; do not label a freely selectable legacy profile as an authenticated Added by me account. A legacy filter=mine request renders All with a clear account-group-only notice, not another user's or account's list. Archive remains its existing shared view with no Mine control; do not repurpose the shared renderer to silently add archive filtering.
- New ordinary navigation after a group switch opens default All. A manually revisited Mine URL is freshly evaluated in the now-current account group, not its former group. Back/reload/filter switch never restores foreign/stale group data or grants mutation authority; retained private router/UI state must be invalidated by existing context boundaries. Authentication removal/logout/expiry gets the normal access error rather than silently falling back to legacy or empty Mine.
- Distinguish empty shared list from empty Mine. Empty Mine offers Show all titles and real Add title; no fake personal list or auto contribution. Loading/retry/error preserve a valid requested filter; safe invalid mode/input notices are visible. Filter changes are reads and cannot write history/contributions/profile or issue provider lookups; existing independent mandatory expiry cleanup stays allowed.

## Implementation choices and checks

`parseWatchlistFilter` accepts only absent/all/mine. Repeated/array/bracket-style filter syntax maps to All with a fixed notice; unrelated query IDs are ignored. `readWatchlist` authorizes the actual current request, applies a bound same-group/title/member EXISTS predicate for Mine and applies that same visible-title predicate to mood and complete contributor projections. It does not change order or filter contributor chips. Account active views return filter capability; legacy/archive keep their previous shared result shape except a legacy-Mine notice.

Account active watchlists use a small local read boundary: native same-origin link navigation, hidden pagehide snapshots and live reload on history/BFCache restoration. It exists only while that watchlist is displayed and removes its listeners on unmount. This deliberately favors fresh membership/group reads over restoring a private client-router snapshot after group switch/removal/contribution changes. Skip links, modifier/new-tab navigation and external/download links retain normal behavior. No global routing/auth policy or persistent client filter state is added. Existing retry refreshes the same requested URL; ordinary new group navigation still uses /watchlist All.

Named fixtures: `tests/watchlist-filter.test.ts`, `tests/accounts/watchlist-mine.test.ts`, `tests/watchlist-view.test.tsx` and `tests/fixtures/watchlist-mine-browser-check.mjs`. The real production browser uses two accounts/two groups at375/1280, manual/provider/joint contributions and actual actions/SQLite. It verifies fresh document requests on back, current-group reevaluation, removed-account denial, inactive full attribution, same-ID archive/restore/history, invalid/array/forged URL claims, direct forged/duplicate/expired cookies, distinct empty/error/filter states and retained retry. A test-only counter records only the word request per outbound provider call and proves reads make none; no URL/key/payload is logged. It snapshots actual business/profile/provenance/session data and preserves an already open picker's inputs/result. Its deliberate isolated read-error case temporarily renames/restores only that fixture's moods table, so Try again exercises real production error recovery without an application bypass. Owned privacy/sentinel/artifact/process cleanup and normal-data isolation remain mandatory.

No schema, dependency, provider/genre/rating filter, personal title copies or picker changes were introduced. All/Mine affects inclusion only, not completion/ratings/notes or imported-field expiry ownership. Optional WATCHNEXT_VISUAL_CHECK=1 briefly holds synthetic-only Mine/empty/error screenshots inside the owned fixture root, then audits/removes them; no credentials or normal data are retained.

# YouTube discovery contract — issue #36

Implementation refresh: October 19, 2026. [#36](https://github.com/xiaodlb/watchnext/issues/36) supplies the offline/mock-verified server contract below; it is not live-provider evidence or a QA verdict. [#38](https://github.com/xiaodlb/watchnext/issues/38) owns actual candidate cards/autofill/previews. Existing strict link lookup/manual fallback and account/legacy context behavior remain usable throughout.

## Delegated defaults

These are engineering defaults, not additional user answers. Use native fetch/crypto and existing normalized/review storage; no SDK or new API service.

- Title input is explicit submit, trimmed 1–200 Unicode code points without controls; supported video ID/link uses the existing strict parser. A malformed URL-like input must not silently become an arbitrary fetch or accidental title search. An explicit server-discriminated title/link intent is suitable; retain existing link callers.
- One search call uses fixed Google /youtube/v3/search, part=snippet, type=video, order=relevance, maxResults=10. One batched /youtube/v3/videos call enriches those unique IDs with snippet/contentDetails/status/liveStreamingDetails; no per-result call loop.
- Preserve search order, validate exact requested ID matches, omit inaccessible/private/deleted/invalid candidates honestly, never accept unrelated detail IDs. Unknown/upcoming/live runtime remains null/manual-required; retain a valid accessible candidate whose runtime is missing. Existing integral full-item seconds bound 1–86400 remains; do not round/fabricate.
- Candidate contract adds compatible optional normalized channelTitle, full-item duration and retrieval/freshness evidence plus page navigation. Kinopoisk callers can keep their existing supported fields and adopt the contract in #37. Channel is search/review display metadata; no durable title-column addition is needed here.
- Server review service supports YouTube candidate selection/detail and explicit pagination, binding query, namespace, current mode/session/group/member/context epoch. Client receives opaque random handles, never authority to provide raw Google page tokens or arbitrary selected IDs. After asynchronous fetch, recheck the same live context; removed/rejoined/switch-away-back/logout/recovery contexts cannot revive.
- Chain bound is five pages (at most fifty candidates visited), ten-minute review/page lifetime and existing twenty-review-per-context bound. New query starts a new chain; stale or foreign/tampered pagination has a safe error/restart. Next/Previous may revisit provider pages explicitly; no crawler/prefetch or automatic retries. Every page request is accounted for even when empty/filtered; missing page tokens mean no navigation.
- Whole logical search+batch shares one ten-second deadline (configurable only within current supported bounds) and cancellation; redirects are rejected and key stays header-only, no-store. Bound parsed response bytes/items and provider concurrency/admission. Suitable defaults: two active/eight waiting requests, thirty-second queue wait, twenty logical lookups per context per 15 minutes and a bounded expiring map; document process-local limits. Queue/timeout/cancel release work. These local limits are not Google quota allocation or distributed guarantees.
- Accept only provider-published HTTPS thumbnails on a small explicit YouTube thumbnail-host allowlist (initial project default i.ytimg.com; add other hosts only with recorded evidence), with no credentials, fragments, nondefault ports or private/arbitrary host destinations. Do not synthesize a thumbnail from an ID or download/cache image bytes. Missing/unsafe image normalizes to null and does not block selection; #38 supplies no-referrer/fallback presentation.
- Persist candidates/channel/thumbnail/duration only in existing short-lived review/page snapshots, retaining retrieval evidence and original policy deadline. Actual local expiry deletes payloads; no stale retained page cache. Existing saved-field origin/refresh/delete behavior remains. Expired pages cannot resurrect old values through save/pagination; fresh selected detail has its own actual retrieval time.

## Current primary evidence

Rechecked October 19, 2026 without secrets, credentials, purchases or live API requests:

- [search.list](https://developers.google.com/youtube/data/reference/rest/v3/search/list) publishes video-only filtering, snippet result page tokens and maxResults. Search snippets do not supply the required runtime.
- [videos.list](https://developers.google.com/youtube/data/reference/rest/v3/videos/list) supports batch video IDs and costs one unit; [video resource](https://developers.google.com/youtube/data/reference/rest/v3/videos) supplies channelTitle, thumbnails, ISO8601 duration and live/status details. Preserve current strict ISO duration/live rules.
- [Current quota overview](https://developers.google.com/youtube/data/determine_quota_cost) describes a separate search bucket of 100 calls/day at one unit per call and a default 10,000-unit pool for other endpoints. Additional search pages incur another request. These current published defaults supersede historical 100-units/search claims; actual account entitlement is unverified. A search page plus enrichment is one search-bucket call plus one videos-list unit.
- [Developer Policies III.E.4](https://developers.google.com/youtube/terms/developer-policies) permits limited non-authorized data storage only temporarily and requires refresh/delete within thirty calendar days. The existing stricter ten-minute review expiry applies to discovery snapshots; field acquisition origins/deadlines must not be relabeled user-origin merely to retain provider data. No OAuth/private-owner data, player, media download or license certification is added.

## Implemented service/action contract

- `beginReview(db,request,'youtube',string,providers,origin,now)` preserves old strict link/ID callers. Explicit `{kind:'title',text}` accepts a title or resolves a supported ID/link directly; malformed URL-like inputs never fall back to search. `lookupTitleAction(contextKey,form)` accepts optional `queryKind=title` for that explicit intent, with existing source/query fields. Omitting it keeps old link behavior. No UI selector/card was added here.
- Search returns `kind=candidates` (or honest `no_match`), optional channelTitle, duration/manualFields and actual retrieval/freshness, plus a random review handle. Page metadata is `{number,next?,previous?,limitReached}`; navigation values are opaque review handles, never raw provider tokens. A candidate snapshot cannot itself be saved.
- `selectReviewCandidate` and existing `selectCandidateAction` support both namespaces. The chosen ID must be in that current snapshot; fresh actual detail is fetched, then snapshot/context are revalidated before a new detail review is returned. Only the existing trusted shared-save path can persist a completed review.
- `pageReview(db,request,handle,'next'|'previous',providers,origin,now)` / `pageCandidatesAction(contextKey,form)` accept only a bound handle and explicit direction. The private snapshot owns provider/query/raw navigation tokens. The chain anchor shares an atomic five-request counter across branching/replayed/concurrent handles, counting the first page, Previous requests and empty/filtered/failed admitted pages. It never silently prefetches. After the cap navigation is omitted with limitReached; start a new explicit query.
- A new YouTube query (including a strict link) physically deletes the context's old search pages/anchor and invalidates pending old search results. Each chain expires ten minutes after its first request; page visits never extend it. All anchor/page/detail snapshots share the existing twenty-review bound and context binding (mode/session/group/member/session revision/membership lifecycle generation). Removal/rejoin, logout/recovery and away/back switching cannot revive them. Empty pages retain navigation only when supplied by the provider; missing tokens end that direction.
- The only server-side raw page-token copy is in the private short-lived snapshot, not client candidates, app URLs, logs or an extra cache. Existing secure-delete maintenance physically removes expired candidate/channel/thumbnail/duration and page payloads. Actual fresh selected details have independent retrieval evidence and saved-field thirty-day policy. No durable channel schema or provenance relabeling was introduced.

Process-local pool/budget and response bounds are in [adapter](youtube-adapter.md#discovery-bounds-and-38-handoff). Their implementation is a delegated engineering choice, not an extra user answer. Query/candidate UI generations, no-referrer image fallback and presentation remain #38; compatible Kinopoisk enhancements remain #37.
